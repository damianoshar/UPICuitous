# The Android build - what owns what

The Android project in `Builds/Android/` is **generated by Projucer** from
`UPICuitous.jucer`, with exactly one exception (the NDK version). This page
says which file owns which setting, so a Projucer resave cannot silently
undo the work.

## The short version

| Setting | Where it lives | Resave-safe? |
|---|---|---|
| min SDK 24 | `.jucer`: `androidMinimumSDK="24"` | yes |
| compile + target SDK 35 | `.jucer`: `androidTargetSDK="35"` | yes |
| Android Gradle plugin 8.10.0 | `.jucer`: `gradleWrapperVersion="8.10.0"` | yes |
| gradle wrapper 8.11.1 | `.jucer`: `gradleVersion="8.11.1"` | yes |
| the debug keystore | `.jucer`: `androidKeyStore*` | yes |
| the app version (the manifest) | `.jucer`: the project `version` | yes |
| the theme, the mic permission, the JNI define | `.jucer`: the ANDROIDSTUDIO exporter | yes |
| the two product flavours (`debug_`, `release_`) | Projucer generates them | yes |
| **the NDK version 28.1.13356709** | **Projucer hardcodes 26.2 - `scripts/fix_android.ps1` puts it back** | **needs the script** |
| **the release signing (fail closed)** | **`scripts/fix_android.ps1` - Projucer always signs with the debug key** | **needs the script** |
| **the permission set** | **the `.jucer` sets it, the script removes POST_NOTIFICATIONS and sets `allowBackup=false`** | **needs the script** |

## The permissions the app asks for

Only three, and each one is used:

| Permission | Why |
|---|---|
| `RECORD_AUDIO` | the microphone (Mon / Capture / the Live tab) |
| `INTERNET` | the phone controller binds a UDP socket for the OSC scrub |
| `CHANGE_WIFI_MULTICAST_STATE` | it joins MobMuPlat's multicast group |

The media permissions (`READ_MEDIA_AUDIO`, `READ_MEDIA_IMAGES`,
`READ_MEDIA_VIDEO`), the storage permissions and `POST_NOTIFICATIONS`
are **not** asked for: the file chooser goes through the Storage Access
Framework, the app reads no images or video, and it posts no
notifications.

`androidPushNotifications` stays **on** in the `.jucer` even so: in
JUCE 8.0.16 it is what selects the `com.rmsl.juce.JuceActivity` activity
class (and with it the `JuceActivity`/`Receiver` java sources). Turning it
off would silently change the launcher activity to `android.app.Activity`
and leave the manifest pointing at classes that are not in the APK. The
*permission* is removed by `scripts/fix_android.ps1` instead.

`android:allowBackup="false"` is set by the same script: the piece files
and the recorded takes should not end up in a cloud backup.

The exporter's settings are the attributes of the `<ANDROIDSTUDIO>` element
in the `.jucer`. Watch the name of the Android Gradle plugin one: in
Projucer's source it is `Ids::androidPluginVersion`, but that identifier's
*string* is `"gradleWrapperVersion"` (a legacy name kept for backward
compatibility - see `jucer_PresetIDs.h`). So the attribute in the file is
`gradleWrapperVersion`, while `gradleVersion` is the gradle *wrapper*
version. Getting that wrong means the attribute is silently ignored and
the resave writes the Projucer default back.

## After a Projucer resave

```
.\scripts\fix_android.ps1
```

It rewrites the one line Projucer cannot express (the NDK version), sets the
manifest's version from the `.jucer`, and then **verifies** every value above
against the `.jucer`. If something is off, it says what and exits 1.

```
.\scripts\fix_android.ps1 -Verify
```

checks without changing anything (use it in CI or before a build).

## Why the NDK is a script and not a setting

Projucer's Android exporter writes the NDK version as a literal:

```cpp
// JUCE/extras/Projucer/Source/ProjectSaving/jucer_ProjectExport_Android.h
mo << "def ndkVersionString = \"26.2.11394342\"" << newLine << newLine;
```

There is no exporter setting for it, so a resave always puts 26.2 back.
This repo builds with **28.1.13356709** (the NDK the tablet build was
verified with), so the script owns that one line.

## The version

`.\scripts\build.ps1 -Version 0.28.0` writes the version into three places:

* `Plugin/CMakeLists.txt` (the VST3),
* `Source/Main.cpp` (`getApplicationVersion()` - the desktop app),
* `UPICuitous.jucer` (the project version - the Android manifest's
  `versionName` and the generated IDE projects).

The `.jucer` edit is XML-safe: the script parses the result before writing
it, and it warns (without writing) if the version could not be found.

## Building the APK

The APK is built in Android Studio (the project is a normal Gradle
project):

* open `Builds/Android` in Android Studio, or
* `.\gradlew.bat assembleDebug` (the flavour is `debug_`, so the APK lands
  in `app/release_/...` - the per-flavour build dirs are gitignored).

Requirements: JDK 17, Android SDK 35, NDK 28.1.13356709, CMake 3.22.1.
`local.properties` (the SDK path) is per machine and gitignored.

The two flavours exist because the JUCE CMake build needs a different
`JUCE_BUILD_CONFIGURATION` per build type; the `variantFilter` keeps the
flavour and the build type in step.

## The device behaviour

* The mic permission is asked for the first time it is needed - press
  **Mon**, **Capture**, or **Play** on a page with live arcs. Opening the
  Live tab does not ask for it (v1.17).
* Save/Load/Render/Sample-loading use the system document pickers.
* Rotate freely: the layout reflows, the app does not restart.

## The file list in the `.jucer`

`Source/` is the only group, and it is current: `Main.cpp`,
`MainComponent.cpp/.h`, `ScoreEditor.h`, `WaveformEditor.h`,
`EnvelopeEditor.h`, `UpicModel.h`, `UpicEngine.h`, `LivePitch.h`,
`AndroidBars.h`, `ModelSnapshot.h`, `MidiHub.h`, `AsioConfig.h`. A new
header in `Source/` has to be added there, or a resave will drop it from
the generated project.

All headers are now listed in the `.jucer`.
