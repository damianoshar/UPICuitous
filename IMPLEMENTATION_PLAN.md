### Notes on what changed along the way

- **JUCE 8.0.16 restructured the modules.** `juce_audio_processors` now
  depends on a new `juce_audio_processors_headless`, the VST3 SDK moved
  into it, and `juce_gui_basics` is split into five compilation units. The
  `.jucer` and `scripts/fix_android.ps1` follow all of that.
- **`INTERNET` stays.** The security review called it unnecessary, but
  that was written against the pre-OSC code. The phone controller binds a
  UDP socket, so Android needs it.
- **`androidPushNotifications` stays on.** In JUCE 8.0.16 it is what
  selects the `com.rmsl.juce.JuceActivity` activity class. Turning it off
  would silently change the launcher activity and drop the
  `JuceActivity`/`Receiver` java classes that the manifest references.
  The *permission* is removed instead.
- **The Gradle wrapper properties are regenerated by Projucer**, so
  `scripts/fix_android.ps1` puts the `distributionSha256Sum` back.
- **The Python and web prototypes are gitignored here** (only
  `python-upic/test_upic.wav` remains), so S-07 does not apply to this
  repository.
- **5.3 (MainComponent refactor) is in progress** on
  `feature/refactor-maincomponent`. So far:
  1. the overlay panel types moved to `Source/OverlayPanels.h`,
  2. the 1400-line constructor split into 19 named `build*()` methods,
  3. the OSC receiver and its endpoints moved to `Source/OscScrubReceiver`,
  4. the sieve row, the arc list, the MIDI controls and the material tabs
     split into their own `build*()` methods,
  5. the overlay card layout moved out of `resized()`,
  6. the audio block split into named helpers (the monitor mix, the score
     fade, the master mix, the stop fade, the scrub preview and the freeze),
  7. the material tabs split into the tab strip, the PM controls and the
     sample controls.

  Every step was verified mechanically (a script compares the old and the
  new file and confirms every code line sits at the same brace depth - only
  the boundaries moved) and by the 368-check selftest, the VST3 smoke test
  and the Android build.

  The largest method left is `resized()` (the flow layout - it is one
  algorithm, so it stays together). The next candidates are the MIDI and
  the sieve sections, which could become their own classes, and
  `renderScoreBlock()`, which could move into the engine.

### 1.3 Add Project/State Size Limits (S-03) — HIGH
**Files:** `Source/UpicModel.h`, `Source/MainComponent.cpp` (`loadFileAsString`, `loadFromVar`), `Plugin/PluginProcessor.cpp`  
**Limits to enforce:**
| Item | Limit |
|------|-------|
| Max project JSON size | 10 MB |
| Max pages per project | 100 |
| Max arcs per page | 500 |
| Max points per arc | 1000 |
| Max envelopes | 50 |
| Max points per envelope | 1000 |
| Max waveforms | 200 |
| Max frames per sample slot | 60 sec × 48 kHz = 2.88 M |
| Max total decoded sample data | 50 MB |
| Max base64 string length (pre-decode check) | 40 MB |
| Max sieve remainders | 5000 |

**Implementation pattern:**
```cpp
// In loadFileAsString()
constexpr size_t MAX_PROJECT_SIZE = 10 * 1024 * 1024;
if (file.getSize() > MAX_PROJECT_SIZE) throw std::runtime_error("Project too large");

// In loadFromVar() - before parsing
if (jsonString.size() > MAX_PROJECT_SIZE) throw std::runtime_error("Project too large");

// In SampleSlot::fromVar()
const size_t expectedDecoded = frames * 2 * sizeof(float); // stereo
if (base64String.size() > expectedDecoded * 1.5) throw ...; // ~1.33x is max base64 overhead
```

**Acceptance:** Maliciously large files rejected gracefully; valid projects up to limits load correctly; `UPICuitous.exe --selftest` PASS.

### 1.4 Add Finite Checks & Clamping (S-03) — HIGH
**Files:** `Source/UpicModel.h`, `Source/UpicEngine.h`, `Source/LivePitch.h`, `Source/MainComponent.cpp`  
**Where to add checks:**
- `masterGain` load: `masterGain.store(std::clamp(val, 0.0f, 1.5f))`
- `intensity`: `std::clamp(val, 0.0f, 1.0f)`
- PM fields: `std::clamp(val, -10.0f, 10.0f)` (or UI range)
- `std::stod` / `std::stof` results: reject if `!std::isfinite(val)`
- `juce::jlimit` wrapper that returns 0 for NaN: `auto safeLimit = [](auto v, auto lo, auto hi){ return std::isfinite(v) ? std::clamp(v, lo, hi) : lo; };`
- `readMaterial()`: guard `while (pos >= matDur && matDur > 0.0) pos -= matDur;`
- `loadSampleIntoSlot()`: clamp `reader->sampleRate` to `44100..96000`; cap `lengthInSamples` to 60 sec × rate

**Acceptance:** No NaN/Inf reaches audio thread; `UPICuitous.exe --selftest` PASS; fuzz testing with NaN/Inf inputs doesn't crash.

### 1.5 Harden `PluginProcessor::setStateInformation()` (S-03) — HIGH
**File:** `Plugin/PluginProcessor.cpp`  
**Changes:**
```cpp
void PluginProcessor::setStateInformation (const void* data, int sizeInBytes) {
    // Reject null/oversized
    if (!data || sizeInBytes <= 0 || sizeInBytes > 10 * 1024 * 1024) return;
    
    // Copy to avoid host buffer lifetime issues
    juce::MemoryBlock state(data, (size_t) sizeInBytes);
    
    try {
        auto v = juce::JSON::parse(state.toString());
        if (!v.isObject()) return;
        
        // Parse on background, swap on message thread
        auto* mc = dynamic_cast<MainComponent*>(getActiveEditor() ? getActiveEditor()->getParentComponent() : nullptr);
        if (mc) {
            mc->getMessageThread()->callAsync([mc, v]() {
                mc->loadFromVar(v);
            });
        }
    } catch (...) {
        // Log, don't crash host
        juce::Logger::writeToLog("Plugin state parse failed");
    }
}
```

**Acceptance:** Null/oversized/malformed state doesn't crash host; valid state restores correctly; VST3 smoke test PASS.

## Phase 2: CI/CD & Supply Chain (Week 2-3)

### 2.1 Split Release Workflow (S-01) — HIGH
**File:** `.github/workflows/release.yml`  
**New structure:**
```yaml
jobs:
  build-android:
    runs-on: ubuntu-latest
    permissions: { contents: read, id-token: write }
    steps: [checkout(persist-credentials: false), setup, build, upload unsigned APK as artifact]
  
  sign-android:
    needs: build-android
    runs-on: ubuntu-latest
    environment: android-signing  # protected env with required reviewers
    permissions: { contents: read, id-token: write }
    steps: [download artifact, fetch keystore from env/secrets, sign, apksigner verify, upload signed APK]
  
  build-windows:
    needs: build-android
    uses: ./.github/workflows/windows.yml  # reuse existing
  
  publish-release:
    needs: [sign-android, build-windows]
    runs-on: ubuntu-latest
    permissions: { contents: write }
    steps: [download signed APK + Windows binaries, generate SHA256SUMS, create release]
```

**Acceptance:** Release workflow runs end-to-end; keystore never in build job; `apksigner verify` PASS; release published with checksums.
